# 평면 컴프 전환 — 씬 컴프를 없애고 한 타임라인에 모두 놓는다

작성일: 2026-08-15
대상: `backend/manifest.py`, `backend/timeline.py`, `cep/com.autokairos.pd/jsx/build_scene.jsx`,
`cep/com.autokairos.pd/jsx/place_on_timeline.jsx`(제거), `cep/com.autokairos.pd/js/storyboard.js`

## 목적

편집할 때 컴프를 들어갔다 나왔다 하지 않게 한다. 지금은 씬마다 컴프를 만들고 Final에
중첩하므로, 한 씬의 인물을 옮기려면 그 씬 컴프로 들어갔다 나와야 한다. 씬 127개면
컴프도 128개다.

SEMOJI TOOL 방식으로 간다 — **컴프는 하나**, 모든 씬의 레이어가 이름 규칙과 시각
구간으로 구분된 채 한 타임라인에 놓인다.

## 지금 구조와 무엇이 바뀌나

`build_scene.jsx`가 씬마다 `proj.items.addComp(name, 씬이미지폭, 씬이미지높이, ...)`를
만들고, Final(1920×1080)에 `fc.layers.add(씬컴프)` + 채움 스케일로 얹는다.

**씬 컴프가 좌표계 역할을 하고 있다.** 컴프 크기가 씬 이미지 크기와 같아서 레이어의
bbox 좌표가 그대로 맞는다. 평면으로 가면 그 역할을 대신할 것이 필요하다.

| | 지금 | 평면 |
|---|---|---|
| 컴프 | 씬 127개 + Final | Final 하나 |
| 좌표계 | 씬 컴프가 씬 이미지 크기 | 매니페스트가 컴프 좌표로 변환해 내보냄 |
| 씬 손잡이 | Final의 씬 컴프 레이어 | `S{번호}_가이드` 널 |
| 카메라 | Final의 씬 컴프 레이어 | 가이드 널 |
| 씬 재배치 | `place_on_timeline.jsx`가 컴프를 놓음 | `S{번호}_` 레이어를 지우고 다시 넣음 |

## 결정 1 — 배율은 세로 기준, 좌우는 배경색으로 채운다

```
f = 1080 / 씬이미지높이
```

위아래를 한 픽셀도 자르지 않는다. 폭이 남으면 좌우에 여백이 생기고, 그 자리는 테마
배경색 솔리드가 채운다.

실제 코퍼스 기준 결과다.

| 씬 이미지 | 장수 | f | 배치 결과 |
|---|---|---|---|
| 1792×1024 | 542 | 1.0547 | 1890×1080 — 좌우 15px씩 |
| 1536×1024 | 8 | 1.0547 | 1620×1080 — 좌우 150px씩 |
| 900×600 | 11 | 1.8 | 1620×1080 — 좌우 150px씩 |

**채움(cover)을 쓰지 않는 이유:** 채움은 위아래를 자른다. 1792×1024면 8.5px씩이라
작지만, 인물의 발이나 자막이 그 안에 걸리면 잘린다. 세로 기준은 그 위험이 없다.

**배율을 벡터화로 대신할 수 없다.** SVG는 키워도 안 깨지지만 그것은 화질 문제이고,
잘림은 화면비 문제다. 1792×1024(1.750)와 1920×1080(1.778)의 비율 차이는 벡터로
없앨 수 없다.

크기가 다른 씬은 각자 자기 이미지 크기로 f를 계산한다. 예외 크기를 따로 다루지 않는다.

**16:9보다 가로로 긴 씬은 좌우가 잘린다.** 1000×500(2.0)이면 f=2.16이라 폭이
2160px가 되어 좌우로 120px씩 넘친다. `ox`가 음수가 되고 여백 솔리드는 만들지 않는다.
세로 기준 규칙의 당연한 귀결이며, 이런 씬은 코퍼스에 5장 있다.

## 결정 2 — 좌표는 백엔드가 구워서 내보낸다

`manifest._scene_layers`가 컴프 좌표로 변환해 내보낸다.

```
f  = 1080 / 씬이미지높이
ox = (1920 - 씬이미지폭 × f) / 2
위치 = [씬좌표x × f + ox, 씬좌표y × f]
크기 = 씬배율 × f
발밑 = [발밑x × f + ox, 발밑y × f]
```

`position`·`scale`·`foot` 셋 다 변환한다. **모든 레이어가 `position`과 `scale`을
갖는다** — bbox가 없는 풀프레임 레이어(배경판·레거시)도 매니페스트가 중앙 위치와
`f × 100`을 실어 보낸다. jsx는 받은 숫자를 찍기만 하고 계산하지 않는다.

**배율을 가이드 널에 싣지 않는다.** AE는 페어런팅 시점의 월드 변환을 보존하므로,
널을 먼저 만들고 자식을 붙인 뒤 널 배율을 바꾸면 자식 값이 어긋난다. SEMOJI가
가이드에 620%를 걸 수 있었던 것은 사람이 순서를 지켜 가며 손으로 다뤘기 때문이다.
숫자를 백엔드에서 구워 넣으면 그 함정이 없고, 변환이 맞는지 pytest가 본다.

## 결정 3 — 이름 규칙이 씬 그룹을 정의한다

레이어 이름의 `S{번호}_` 접두사가 "이 씬의 레이어"를 뜻한다. 씬 번호 표기는
`timeline.comp_num`을 그대로 쓴다 — 정수는 두 자리 0채움, 삽입 씬의 소수 번호
25.25는 `25_25`.

```
S12_가이드                ← 씬 손잡이(널). 카메라가 잡는다
S12_01_노란옷아이          ← 요소. 앞 두 자리가 z 순서(작을수록 뒤)
S12_01_노란옷아이_피벗      ← 까딱까딱 널(jsx가 만든다)
S12_02_흰색전기차
S12_배경                  ← 인페인팅된 배경판
S12_판                    ← 좌우 여백을 채우는 배경색 솔리드
S12_음성                  ← 오디오
S12_제목                  ← 레이아웃 씬의 텍스트·셰이프
```

요소 이름은 사이드카의 한국어 `name`을 쓰고, 없으면 파일 stem을 쓴다. 이름에 공백이
있어도 된다 — 우리는 접두사로만 찾는다.

`aeName`을 매니페스트가 정해서 내보낸다. jsx가 이름을 조립하지 않는다.

## 결정 4 — 쌓임 순서

타임라인은 **씬 번호대로 위에서 아래**다. 씬 1이 맨 위에 온다.

한 씬 그룹 안의 순서는 위에서 아래로:

```
요소(z 큰 것이 위 = 앞)
배경
판
가이드 널
```

씬끼리는 시각이 겹치지 않으므로 그룹 사이 순서가 화면에 영향을 주지는 않는다. 편집할
때 눈으로 찾기 위한 규칙이다.

## 결정 5 — 씬 단위 삽입·교체

패널의 ⤓(이 씬을 타임라인에 배치)와 씬별 빌드가 같은 동작을 한다.

1. 컴프에서 `S{번호}_`로 시작하는 레이어를 **전부 지운다**.
2. 그 씬의 레이어를 다시 만든다.
3. 다음 씬 그룹(`S{다음번호}_`의 첫 레이어) **바로 위에** 놓는다. 다음 그룹이 없으면 맨 아래.

컴프를 오갈 일이 없다. `place_on_timeline.jsx`는 씬 컴프를 전제로 하므로 제거하고,
패널의 ⤓ 버튼은 씬 빌드 경로를 부른다.

**대상 컴프는 `Final`이다.** 활성 컴프를 쓰지 않는다 — 다른 컴프를 열어 둔 채 버튼을
누르면 엉뚱한 곳에 쌓인다. 없으면 만든다. 자막(`subtitle_layers.jsx`)이 이미 `Final`을
대상으로 하므로 이름을 바꾸지 않는다.

## 결정 6 — 시각

`timeline.build_plan`이 주는 씬 시작·길이를 그대로 쓴다. 매니페스트의 각 씬에
`start`와 `duration`을 싣는다.

- 모든 레이어: `inPoint = start`, `outPoint = start + duration`
- 오디오: 추가로 `startTime = start` — 이것이 없으면 소리가 0초부터 재생된다
- 모션 키프레임: 씬 상대 시각이 아니라 `start + 오프셋`
- 카메라: 가이드 널에 `start`부터 `duration` 동안

컴프 길이는 마지막 씬의 끝까지 늘린다.

## 결정 7 — 레이아웃 씬

차트·지도 같은 레이아웃 씬도 평면으로 푼다. 셰이프·텍스트가 수십 장 나오지만 가이드
널에 묶여 접힌다.

`renderLayout`은 지금 씬 컴프 크기 `(cw, ch)`와 `S = W/1920`으로 그린다. 평면에서는
`W=1920, H=1080, S=1`로 컴프 좌표에 바로 그린다. 그린 레이어를 가이드 널에 붙이려면
어디까지가 이번 씬 것인지 알아야 하므로, **그리기 전후의 `comp.numLayers`를 기록해
그 구간의 레이어에 접두사를 붙이고 페어런팅한다.**

지도 오버레이(`renderMapOverlay`)도 같다.

## 오류 처리

| 상황 | 처리 |
|---|---|
| 씬 이미지 크기를 못 읽음(PIL 없음/깨짐) | f를 1.0으로 두고 1920×1080으로 취급. 로그에 남긴다 |
| 씬 이미지 높이가 0 이하 | 그 씬은 좌표 변환 없이 넘기고 로그에 남긴다 |
| `Final` 컴프 없음 | 만든다 |
| 다른 컴프가 열려 있음 | 무시하고 `Final`에 넣는다 |
| 좌우 여백이 없음(f×폭 ≥ 1920) | `S{n}_판`을 만들지 않는다 |
| 레이아웃 씬에 이미지 없음 | 지금처럼 셰이프·텍스트만 그린다 |

## 테스트

pytest로 검증한다.

- 좌표 변환: 1792×1024 → f=1.0547, ox=15.0 / 1536×1024 → ox=150.0 / 1920×1080 → f=1.0, ox=0
- 위아래가 잘리지 않는다: 어떤 입력에서도 변환된 y가 0~1080 밖으로 나가지 않는다
- 모든 레이어에 `position`과 `scale`이 있다 — bbox 없는 레이어도
- `aeName` 규칙: `S12_01_노란옷아이`, 배경 `S12_배경`, 소수 씬 `S25_25_배경`
- 씬 `start`·`duration`이 `timeline.build_plan`과 일치한다
- 여백이 없는 씬(16:9 정확)에는 `bgFill`이 없다
- `foot`도 같은 변환을 거친다(까딱까딱 피벗이 발밑에 오도록)

**자동 검증이 안 되는 것:** AE에서의 실제 배치·삽입·교체·카메라 동작. 이 맥에
After Effects가 설치돼 있지 않다. 테스터 PC에서 확인해야 한다. 특히 씬 그룹을 지우고
다시 넣을 때 다른 씬을 건드리지 않는지, 순서가 유지되는지는 사람이 봐야 한다.

## 범위 밖 — 다음 설계로

- **SEMOJI 기능 이식**: 모션 프리셋 종류별 개방 + `stamp`·`wiggle` 신규, 출처 자막,
  패널 도구 구역(SRT 가져오기·널 끼우기·프리셋 수동 적용). 가이드 널과 평면 구조가
  전제라 이 문서 다음에 온다.
- **캐릭터 부위 분리**: 잘라 낸 캐릭터를 다시 layerize로 머리·몸통·팔·다리로 쪼개고
  부위를 몸통에 페어런팅하는 것. 좌표 중첩과 이음매(회전 시 어깨가 뚫림) 문제를
  따로 다뤄야 한다.
- 씬 사이 트랜지션.
- 가이드 널을 패널에서 조작하는 UI.
