# Writing Style

유튜브 나레이션 원고의 문체, 톤, 글자 수 제한, 금지 표현, IMG 마커 규칙을 정의합니다.

**참조 에이전트**: write-manuscript, qa-reviewer

---

## 1. 문체 규칙

### 필수
- **대화체**: "~입니다", "~거든요", "~한번 보시죠"
- **짧은 문장**: 한 문장 최대 40자. 나레이션 호흡 단위
- **능동태**: "연구가 발표되었다" → "연구팀이 발표했습니다"
- **구체적 숫자**: "많은" → "1억 5천만 명의"

### 금지
- 번역체 ("~것이 사실이다", "~함에 있어서")
- 과도한 수식어 ("매우 놀라운 혁명적인")
- 논문체 ("~에 의하면", "~것으로 사료된다")
- 영어 남용 (적절한 한국어 대체 우선)

---

## 2. 후킹 기법 (Act 1 도입부)

1. **충격적 수치**: "단 3년 만에 1000배 성장한 시장이 있습니다"
2. **반전 질문**: "여러분이 쓰는 챗봇, 사실은 에이전트가 아닙니다"
3. **일화**: "2024년 어느 날, 한 스타트업에서..."

---

## 3. 페이싱

- 데이터 씬 뒤에는 스토리 씬 배치
- 3-4개 씬마다 브리딩 포인트
- 챕터 전환 시 짧은 요약 문장

---

## 4. VIZ 마커 — 사용 금지

**⚠️ 원고 작성 단계에서 `[VIZ:...]` 마커를 사용하지 않습니다.**

- 시각화 타입(vizType), 차트 종류, 데이터 구조는 모두 **visual-composer**가 나레이션 내용 + `research_report.json`을 분석하여 결정합니다.
- **asset-advisory**가 `research_report.json`에서 정확한 수치/지표명/단위를 매칭하므로, 원고에 메타데이터 힌트를 남길 필요가 없습니다.
- 원고 작성자는 **나레이션 텍스트 작성에만 집중**합니다.

---

## 5. IMG 마커 — 사용 금지

**⚠️ 원고 작성 단계에서 `[IMG:...]` 마커를 사용하지 않습니다.**

- 이미지 필요 여부, 소스 타입(wikimedia/search/generate), 검색어는 모두 **asset-advisory** (Phase 2.5)가 나레이션 내용 + `research_report.json`을 분석하여 결정합니다.
- 원고 작성자가 이미지 판단을 하면 asset-advisory의 전문적 판단과 충돌하거나, 불필요한 이미지를 강제하게 됩니다.
- 원고 작성자는 **나레이션 텍스트 작성에만 집중**합니다.

---

## 6. 씬 분할 — 원고 작가는 하지 않음

**원고에 씬 번호(`## Scene N:`)나 씬 구분선(`---`)을 넣지 않는다.**
씬 분할은 visual-composer가 나레이션 텍스트를 분석하여 자동으로 수행한다.

원고 작가가 할 일:
- 챕터 내에서 빈 줄로 호흡을 구분
- 하나의 단락에 하나의 개념만 담기 (과밀 방지)
- 자연스러운 서사 흐름에만 집중

visual-composer가 참고하는 분할 신호 (원고 작가가 의식할 필요 없음):
1. "한편", "그런데", "그러나" 등 전환어
2. 새로운 인물 소개
3. 시간/장소 전환
4. 단락 100자 초과

---

## 7. 원고 포맷

```markdown
# Ch1. 챕터 제목

나레이션 텍스트...
빈 줄로 호흡 구분.

다음 단락 이어서...

# Ch2. 챕터 제목

나레이션 텍스트...
```

> **참고**: VIZ 마커 없이 `## Scene N: 제목` + 나레이션만 작성합니다.
> 시각화/차트/에셋 결정은 후속 단계(visual-composer, asset-advisory)가 담당합니다.
