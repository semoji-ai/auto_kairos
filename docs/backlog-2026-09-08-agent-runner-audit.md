# agent_runner 감사 — 잠자는 결함 7건

날짜: 2026-09-08 / 감사자: gpt-6-astra (codex) + 사람 검증 / 상태: **미착수**

> 저장소 통합 작업 중에 돌린 외부 감사 결과입니다. 통합 범위 밖이라 손대지
> 않고 남깁니다. 지적 위치는 전부 `auto_agent/modules/agent_runner.py` 입니다.

## 먼저 — 범위를 좁혀 두겠습니다

**본 파이프라인(Stage 1~3)은 이 파일을 쓰지 않습니다.** 그쪽은
`auto_agent/orchestrator/runner.py` 를 타고, 타임아웃도 제대로 걸려
있습니다(`:2365`, `:3339` 의 `communicate(input=prompt, timeout=timeout_sec)`).

`modules/agent_runner.py` 는 **Stage 0(트렌드 분석)·Stage 4(성과 분석)** 전용입니다.

## ★ 1. 스트리밍 경로에 타임아웃이 없다 — 지금은 잠자는 중

`_run_agent_streaming(…, timeout, …)` 이 `timeout` 을 인자로 받지만 **본문에서
한 번도 쓰지 않습니다**(`:734`).

```python
for line in proc.stdout:      # 파이프가 닫힐 때까지 무기한
    ...
proc.wait(timeout=30)         # 위 루프가 끝나야 도달한다
```

자식 프로세스(`claude` CLI)가 출력 없이 살아 있으면 파이프가 안 닫혀 영원히
멈춥니다. `max_duration_minutes` 로 계산한 값(`:670`)이 통째로 버려집니다.
배치 경로(`:700`)는 `communicate(timeout=timeout)` 으로 제대로 합니다.

**그런데 지금은 안 터집니다.** 스트리밍은 `on_progress` 를 넘겨야 켜지는데
(`streaming = on_progress is not None`) 호출부 셋 다 안 넘깁니다.

```
auto_agent/cli.py:1290                          on_progress 없음
auto_agent/scripts/autoresearch_hourly.py:134   없음
tests/test_agent_runner.py:214                  없음
```

**대시보드에 진행 표시를 붙이려고 `on_progress=` 한 줄을 넘기는 순간** 타임아웃이
사라진 경로가 켜집니다. 무해해 보이는 변경이라 더 위험합니다.

## 2. Stage 4 재실행이 기존 보고서를 먼저 지운다

출력 이름이 날짜·채널로 고정되는데(`:325–330`), 기존 파일 확인 없이 빈 템플릿을
`write_text()` 로 덮어씁니다(`:375–376`). 같은 날 재실행하다 실패하면 **이전
정상 보고서 대신 템플릿만 남습니다.**

임시 경로에서 만들어 검증한 뒤 게시하고 이전 판을 보존하는 쪽이 맞습니다.

## 3. 성과 digest 가 이전 digest 를 입력으로 다시 집는다

digest 는 `insights/performance/_inputs` 에 쌓이는데(`:273–282`), 입력 탐색
대상이 그 **상위** 디렉터리입니다(`:284–293`). 탐색은 하위를 전부 순회해
수정시간순으로 고릅니다(`:1048–1053`).

원자료 대신 **재요약된 자료**가 입력 슬롯을 차지합니다. `_inputs` 를 탐색에서
빼야 합니다.

## 4. Stage 4 가 같은 digest 다섯 개를 두 번 분석한다

주간 리뷰와 피드백 호출을 직렬로 돌리는데(`:413–423`), 두 프롬프트가 같은
digest 다섯 종을 읽습니다(`:537–540`, `:573–576`). 두 번째가 첫 번째 결과를
입력으로 받지 않아 공통 근거를 다시 분석합니다.

합치면 **에이전트 호출 2회 → 1회**입니다.

## 5. Stage 0 래칫이 수렴해도 남은 라운드를 다 돈다

기본 5라운드(`:120–121`)를 순차 호출하는데(`:167–177`) 수렴 종료 조건이
없습니다(`:190–192`). 후보와 점수가 안 변해도 설정한 횟수만큼 부릅니다.

3회에서 수렴하면 호출 40%, 2회면 60% 절감입니다. **점수만 보고 끊으면 내용
개선을 놓치므로 후보 구성 변화도 함께** 봐야 합니다.

## 6. `allowed_tools` 설정이 명령 생성에 전달되지 않는다

`_run_agent()` 는 모델·턴 수·시간 제한은 설정에서 읽는데 `allowed_tools` 는
넘기지 않고(`:667–679`), 명령 생성은 `Read`·`Write`·`Glob`·`Grep` 고정
목록을 씁니다(`:1375–1389`).

현재 설정값이 마침 이 고정 목록과 같아서(`auto_agent/data/agents.json:232–237`,
`:250–255`) **지금 도구가 과하다는 근거는 없습니다.** 다만 설정에서 줄여도
반영되지 않는 것은 결함입니다.

## 7. 신호 파일을 두 번 읽는다

후보 평가에서 읽어 파싱하고(`:1096–1098`, `:1107–1115`), 선택된 파일을 digest
작성에서 다시 읽고(`:1164–1171`), 신호 요약에서 또 파싱합니다(`:1178–1183`).
앞 결과를 다음 단계로 넘기지 않습니다.
