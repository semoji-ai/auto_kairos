# Jev 기반 타겟 리서치 자료 선별

2026-09-20 구현. 기존 v3 PipelineRunner의 targeted-researcher CLI/Codex 프롬프트에만 적용합니다. 별도 v4 파이프라인·직접 실행하는 외부 에이전트에는 자동 적용되지 않습니다. targeted_claims.json 계약은 유지합니다.

## 실제 흐름

research_questions.json의 우선순위 높은 질문부터 검색 도구(Serper) → Jev 검색결과 선택 → HTTP 원문 수집 → Jev 근거 문단 선택 → Jev 충분성 판단을 실행합니다. 충분하지 않으면 두 번째 검색어로 한 번 더 시도합니다. 큰 모델에는 전체 검색 목록 대신 선택한 원문과 URL, 질문별 ready/fallback을 전달합니다. 큰 모델은 답변 합성·근거 조건 확인을 하고, 부족하거나 상충하는 질문은 기존 웹 리서치로 처리합니다.

ready는 진실이나 신뢰도 인증이 아니라 답변 합성을 시작할 자료가 있다는 잠정 판정입니다. 모든 질문은 유지됩니다. PDF·리디렉션·접근 불가·빈 본문은 증거로 사용하지 않습니다. 스니펫을 원문 증거로 바꾸지 않습니다. 완성 원고와 기존 claims는 이 모듈이 수정하지 않습니다.

기존 search_queries가 있으면 최대 두 개를 사용합니다. 없으면 질문 원문과 '원인 과정 근거 원문'을 붙인 결정적 검색어를 사용합니다. Jev가 새로운 검색어를 자유문으로 생성하는 구조는 아닙니다. 새로운 접근·영문 쿼리 생성은 fallback 연구자가 담당합니다.

## 활성화와 제한

- TYPESAFE_API_KEY 및 SERPER_API_KEY가 로드되어 있으면 기본 활성화됩니다. 기존 runner가 워크스페이스 .env를 로드합니다.
- JEV_TARGETED_RESEARCH=0 으로 기존 경로로 복귀합니다. 키가 없으면 자동으로 기존 경로입니다.
- 한 실행당 최대 8질문, 질문당 최대 검색 2회·페이지 수집 2회. 초과 질문은 fallback입니다.
- Jev 모델 jev-1.13.0 고정, 예산 상한 $0.03. 사용량 응답이 없는 실패도 보수적으로 예약 비용에 포함합니다. Serper 비용과 이후 작성/추가 리서치 비용은 별도입니다.
- 새 질문/검색 라운드는 180초가 지나면 시작하지 않습니다. 진행 중 HTTP 요청 때문에 총시간은 이보다 길어질 수 있습니다.
- 큰 페이지·요청에는 길이 제한이 있으며 누락된 후반부 근거가 있을 수 있습니다. 전체 탐색 보장이나 최종 자동 사실검증이 아닙니다.
- 논리적 질문/원고 내용과 모듈 버전의 해시로 24시간 캐시합니다. 원고·질문 변경 시 무효화합니다. 기존 실패 결과도 TTL 동안 유지해 재시도 비용을 억제합니다.

## 기록

프로젝트 research/jev_targeted/<hash>/<run timestamp>/ 아래 packet.json, sources.json, jev_trace.json을 보존합니다. 해시 폴더의 packet.json은 최근 실행 캐시입니다. 외부 자료와 원문 발췌, Jev 판정, 실제 입력 토큰·추정 비용, 검색/열람 횟수를 기록합니다. API 키와 예외 메시지 원문은 저장하지 않습니다.

이 계측은 큰 모델의 실제 회피 토큰/순절감액을 계산하지 않습니다. 큰 모델이 필요에 따라 재조사할 수 있으므로 이익은 실제 작업 단위의 작성·fallback 비용까지 비교해야 합니다. 기존 전체 파이프라인 비용 장부에는 Jev 비용을 합산하지 않았으며 packet.metrics에서 별도 확인합니다.
