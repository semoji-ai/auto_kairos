# Jev 독립 요청 병렬 처리 실험 — 2026-09-22

48개 실제 디아지오 검색노트를 3회 반복 평가한 결과, 요청 8개 병렬 처리는 순차 처리 대비 **7.55배** 빨랐다. 입력 토큰과 추정 비용은 동일했다. 자료 8개를 한 요청에 묶는 방식은 더 저렴했지만, 개별 자료 평가와 판정 차이가 더 컸다. 현재 근거로는 자료별 독립 요청을 제한된 수로 병렬 실행하는 방식이 유망하다. 운영 파이프라인은 변경하지 않았다.

## 방법

- 로컬 디아지오 프로젝트의 source_notes 165개 중 고정 seed 2209로 48개 추출. 원문을 새로 열람하거나 외부 사실 검증하지 않음.
- jev-1.13.0, 각 자료의 관련성·다음 행동·확보된 본문 수준을 Choice 3개로 판정.
- 순차/4개 병렬/8개 병렬: 요청마다 자료 1개와 질문 3개. 세 방식에서 입력은 바이트 수준으로 같으며 SHA256 확인.
- 묶음: 자료 8개와 질문 24개를 한 요청으로 구성하여 총 6요청을 순차 처리. 질문은 같지만 전체 문맥은 다름.
- 각 방식 3회, 실행 순서 회전. 재시도 없음. 동일 호스트, 각 요청마다 새 HTTP 연결, 동시성만 제어. 연결 풀이나 워밍업 없음.
- 총 450요청, 자료 평가 576건, 개별 판단 1,728건. 서로 다른 자료 수는 48개.
- 비용 상한 $0.10 설정. 실제 입력 사용량 684,072토큰 × $0.042/백만 = **$0.028731024 추정**. 계정 청구 내역 확인은 아님. 가격 출처: https://docs.typesafe.ai/models

## 판정 일관성

정답 라벨이 없으므로 다음 수치는 **정확도가 아니라 동일 자료에 대한 판정 일치율**이다.

| 비교 | 일치율 | 다른 판정/전체 비교 |
|---|---:|---:|
| 순차 1회차 vs 순차 2·3회차 | 98.61% | 4/288 |
| 같은 회차 순차 vs 4개 병렬 | 98.61% | 6/432 |
| 같은 회차 순차 vs 8개 병렬 | 98.38% | 7/432 |
| 같은 회차 순차 vs 8자료 묶음 | 83.80% | 70/432 |

순차 반복 자체에도 판정 변동이 있었다. 병렬 방식 차이는 비슷한 규모였으나 통계적으로 동등한 품질을 입증한 것은 아니다. 일부 변동은 단순 인접/직접 관련 분류가 아니라 skip/read 전환이므로 자동 폐기에는 주의가 필요하다.

묶음의 차이 70건은 다음 행동 41건, 관련성 29건이었다. 본문 확보 수준은 모든 비교에서 일치했다. 예를 들어 M002는 개별 평가 reserve에서 묶음 평가 read, M003은 unrelated/skip에서 adjacent/reserve로 바뀌었다. 다른 자료가 포함된 문맥 또는 입력 구조의 영향일 수 있으며, 묶음 판정이 틀렸다고 단정할 수 없다.

## 오토카이로스 적용 판단

검색 결과나 장면별 관찰 기록처럼 서로 독립적인 후보를 자료 단위로 분리하고, 같은 자료에 관한 몇 개 기준은 함께 질문하며, 자료별 요청을 최대 8개 정도 동시에 처리하는 구조가 이번 결과와 맞는다. 실제 운영에서는 계정 제한에 맞춘 큐, 429 백오프, 비용 상한이 필요하다. 8은 최적값이나 최대 한도가 아니라 이번에 검증한 동시성이다.

후보 탐색 단계에서 대량 자료에 대한 관련성·원문 확인 우선순위·확보 수준을 빠르게 분류하는 데 실행상의 실효성이 확인되었다. Sol/Luna가 이후 어떤 자료를 읽고 보강할지 결정할 때 이 분류를 사용할 수 있다. 다만 실제 원문 열람 절감, 중요한 자료 보존, 최종 콘텐츠 품질 및 전체 LLM 토큰 절감은 이번 실험에서 측정하지 않았다.

이번 실험은 ‘요청당 질문 1개’가 우월한지 검증하지 않았다. 자료당 3질문을 유지하여 **독립 자료 간 요청 병렬화**를 검증했다. 동일 자료의 질문까지 무조건 쪼개면 입력 반복 비용이 늘 수 있다. 묶음 요청을 다시 병렬화하는 조합도 이번에는 미측정이다.

다음 실험은 같은 후보 풀에서 Sol/Luna 직접 선별과 Jev 8병렬 사전 분류 후 Sol/Luna 선별을 비교하되, 사람이 지정한 필수 자료 보존율·열람 수·전체 토큰·전체 시간·최종 콘텐츠 품질을 함께 측정하는 것이 적절하다.
