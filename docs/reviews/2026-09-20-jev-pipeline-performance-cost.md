# Auto Kairos 전 단계: 동일 성능 대비 Jev 대체 경제성

2026-09-20. 새로운 제작/API 실험을 추가하지 않고, 현재 pipeline.json·실행 코드·로컬 DB와 기존 Jev 실험 원시 기록을 분석했습니다. 가격은 공식 문서를 이날 확인했습니다. 이 문서는 도입 판단용 분석이며 실제 절감 달성 보고가 아닙니다.

## 결론

Jev는 반복 판단 호출의 비용을 크게 낮출 가능성이 높습니다. 그러나 현재 증거로 전체 파이프라인에서 같은 품질을 유지하며 비용을 몇 % 절감한다고 확정할 수 없습니다. 우선 검증 대상은 원고/씬 래칫의 항목별 검사, 검색 자료의 분류·중복 제거, 이미 관찰된 레퍼런스의 재선별입니다. 생성·픽셀 관찰·음성 청취·렌더를 Jev로 바꿀 수는 없습니다.

판단 호출 단가는 가정한 동등 토큰 작업에서 94~99.7% 낮지만, 전체 절감률은 교체 가능한 작업의 비중과 재검토·재작업에 제한됩니다. 특히 후보를 추가 생성하거나 매번 큰 모델로 입력을 준비하면 Jev 추가 비용만 생길 수 있습니다.

## 5. 재검토와 재작업을 포함한 경제성

기존 판단비를 B, Jev를 J, 추가 입력 준비비를 P, 큰 모델로 넘기는 비율을 r, 넘어간 검토 1회 비용을 E, 추가 오류·재작업 기대비를 W라고 두면:

`새 비용 = P + J + r×E + W`

`절감 조건 = P + J + r×E + W < B`

E가 B와 같다는 보장은 없습니다. 실패 맥락을 읽고 고치면 더 비쌀 수 있습니다. 관찰이 원래 필요했던 작업이면 중복 계상하지 않고, Jev만을 위해 추가된 관찰·요약은 P에 포함합니다.

예를 들어 Sonnet 5 비캐시 가정에서 B=$0.005, J=$0.000084이고 E=B, P=W=0이면 90% 절감을 유지하려면 r≤8.32%여야 합니다. 30%를 상위 모델에 넘기면 절감은 68.32%입니다. 대략 3센트의 추가 준비/재작업이 한 번 생기면, 이 단가의 판단 약 6회에서 얻을 이익을 없앱니다.

관찰 재사용 조건: 기존 관찰+선택 비용 V를 K번 반복하던 경우와, 한번 관찰 V0 후 Jev로 K번 선택하는 경우를 비교합니다. `V0 + K×J + 재검토비 < K×V`일 때 이득입니다. 기존 시스템도 관찰을 캐시했다면 공정한 비교는 캐시된 기존 선택비와 해야 합니다.

## 6. 전체 비용에 미치는 영향: 예측이 아닌 민감도

저장 기록에서 brief-reviewer, manuscript-reviewer, script-reviewer, fact-verifier와 step_2_review의 합계는 $58.45, 전체 $351.66의 16.62%입니다. 이 그룹도 설명·조사·수정이 섞여 있어 전액 교체 가능하지 않습니다. 반면 생성 에이전트 내부에도 별도 판단이 있을 수 있어 이 그룹이 전 시스템의 최대 대체 범위라는 뜻도 아닙니다.

아래는 해당 그룹만 대상으로 하며 Jev/기존 단가 비율 1.68%(위 Sonnet 비캐시 예), 검토 1회 비용 동일, 준비·추가 재작업비 0이라는 가정입니다. 비율은 실험에서 추정하지 않았습니다.

| 리뷰 그룹 내 교체 비중 가정 | 상위 재검토율 가정 | 기록값 기준 절감액 | 전체 기록값 대비 |
|---|---:|---:|---:|
| 25% | 30% | $9.98 | 2.84% |
| 50% | 10% | $25.81 | 7.34% |
| 75% | 5% | $40.91 | 11.63% |

이 수치는 예상 절감 범위나 신뢰구간이 아닙니다. 전체 90% 절감 주장 대신, 교체 비중과 예외율을 먼저 실측해야 한다는 예시입니다. 이미지/TTS 등 빠진 전체 제작비를 더하면 판단 교체만으로 얻는 비율은 더 낮아질 수 있습니다. 반대로 불필요한 재생성을 실제로 줄이면 간접 이익은 커질 수 있으나 현재는 입증되지 않았습니다.

## 7. 도입 우선순위와 동등 성능 검증 설계

1. **반복 원고/씬 래칫의 검사 부분**: 기록상 비용 규모가 있고 입력을 이미 갖고 있습니다. 생성·수정은 유지하고 명시 요건 검사 호출만 교체합니다. 최종 의미 리뷰까지 없애지 않습니다.
2. **자료 분류·중복·관찰된 레퍼런스 선별**: 자료량과 재사용 횟수가 많을 때 효과가 큽니다. 관찰 준비비와 확보 완료율을 함께 측정합니다.
3. **배포 문구 정합·작업 분기**: 작은 결정부터 대체합니다. 규칙·스키마 검사에는 LLM을 쓰지 않습니다.
4. **최종 사실검증·미감·음성·성과 추론**: 동일 성능 근거가 부족해 현재 대체 보류입니다.

동일 실제 입력에 A=현재 운영, B=코드로 가능한 검사를 먼저 제거한 기존 모델, C=코드+Jev+필요 시 상위 모델을 비교합니다. 그래야 코드 최적화 효과를 Jev의 효과로 잘못 계산하지 않습니다. 초기에는 실행 결과를 바꾸지 않는 비교로 측정하고, 프로젝트 단위로 튜닝/검증 자료를 분리합니다.

측정할 단위: artifact/step/model/version, 실제 과금 입력·출력·캐시 토큰, 호출 시간, 입력 준비·판단·재검토·수정 각각의 비용, 실제 제거한 기존 호출, 통과 오류·누락·잘못된 탈락·보류, 사람 수정 시간, 쓸 수 있는 자료 확보율, 생성 재시도 수. 정확한 결함 이유/수정이 필요한 작업은 Jev 선택 결과와 별도 비용으로 기록합니다.

일반 분류는 예를 들어 오류율 증가 허용폭 2%p를 미리 정해 비열등성 신뢰구간으로 판단하고, 중요한 사실 오류는 별도 기준을 둡니다. 이는 제안 기준이지 검증 완료가 아닙니다. 30개 작업은 경제성과 오류 양상을 확인할 파일럿이며 좁은 동등성 입증에는 부족할 수 있습니다. 0/32 실패라도 95% 단측 상한은 약 9%이므로 32/32를 안전성 증명으로 사용하지 않습니다. 중요한 오류·보류 분기는 Jev 자체 확신도만으로 자동 면제하지 않습니다.
