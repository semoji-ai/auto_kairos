# 이미지 검수 규칙 — 3중 교차 검증

> **연출 채점과 이미지 검수는 다른 질문이다.**
> 채점은 메타데이터만 본다. 설계가 잘 됐는지는 알아도 **나온 그림이 실제로 좋은지는 모른다.**
> EP01은 연출 채점 99점을 받은 상태에서 이미지 검수를 돌렸더니 38씬 중 17씬이
> 화풍 3점 이하였다. 프롬프트가 훌륭해도 결과물이 엉망일 수 있다.

---

## 1. 반드시 3개 모델로 본다

한 모델만 쓰면 절반을 놓친다. EP01 1차 검수에서 **제미나이와 코덱스의 판정이
38씬 중 16씬만 일치**했다.

| 모델 | 강점 | 실제로 잡은 것 |
|---|---|---|
| **Gemini** (2.5-pro) | 화풍·시각 일관 | 「안개, 빛 번짐 등 회화적 효과가 기준과 다르다」 — 화풍 붕괴의 진짜 원인 |
| **Codex** | 내용 일치·고증 | 「나레이션의 두 버팀목이 전혀 안 보이고 도자기 공방 장면이 나왔다」 |
| **Claude** (직접) | 표본 확인·교차 대조 | 모델 지적이 실제와 맞는지 눈으로 확인 |

**둘 이상이 문제로 본 씬은 반드시 재작업한다.** 한 모델만 지적한 것은 판단 대상이다.

```bash
python3 scripts/review_images_gemini.py <review_in.json> -o <out.json>
# 코덱스는 같은 기준표로 codex exec 의뢰
# 클로드는 keyVisual과 인물 등장 씬을 표본으로 직접 확인
```

## 2. 기준 그림을 첨부한다 — 말로 설명하지 않는다

검수 프롬프트에 그림체를 **글로 적으면 매번 재해석된다.** 인물 시트를 만들 때
세 번 실패한 그 방식이다([[character-sheet-rules]] 1절).

기준 시트 이미지를 첨부하자 지적이 달라졌다.

```
말로 설명했을 때   "4등신이 아니다"        (모호, 재생성해도 안 고쳐짐)
그림을 붙였을 때   "안개·빛 번짐이 기준과 다르다"  (구체적, 바로 고칠 수 있음)
```

`review_images_gemini.py`가 첫 번째 이미지로 세모지 공식 캐릭터 시트를 붙인다.

## 3. 채점 항목 6가지 (각 1~5점)

| 항목 | 무엇을 보나 |
|---|---|
| **content** | 그림이 나레이션이 말하는 **바로 그 장면**인가 |
| **style** | 기준 시트의 그림체에서 벗어나지 않았는가 |
| **character** | 같은 인물이 다른 씬과 **같은 사람**으로 보이는가 |
| **period** | 복식·건물·소품이 그 연대에 맞는가 |
| **quality** | 구도가 안정적인가. 손·얼굴이 뭉개지지 않았는가. 글자가 박혀 있지 않은가 |
| **layers** | 배경·중경·인물·전경이 층으로 나뉘어 2.5D 모션을 넣을 수 있는가 |

판정은 `keep` / `fix`(재생성 권함) / `reject`(반드시 다시).

### 통과선

- **모든 항목 평균 4.5 이상**
- **두 모델이 함께 문제로 본 씬 0개**
- `reject`가 전체의 10% 이하

## 4. EP01 실적 — 이 방식이 실제로 잡은 것

| 항목 | 1차 | 2차 |
|---|---:|---:|
| **화풍(제미나이)** | **3.4** | **4.5** |
| 내용 일치 | 4.9 | 5.0 |
| 화면 완성도 | 4.6 | 4.8 |
| 판정 | keep 20 / reject 13 | **keep 38 / reject 4** |

1차에서 제미나이가 남긴 말이 사태를 요약한다.

> 인물이 4등신이 아닌 6~7등신, 얼굴 묘사가 사실적, 검은 외곽선 사용.
> **이 화풍으로 시리즈를 계속 진행할 수 없습니다.**

원인 두 가지를 고쳐 해결했다([[character-sheet-rules]] 4-1절).

1. 시트를 **인물이 아니라 화면 전체의 화풍 기준**으로 쓴다
2. 프롬프트에서 **사진 조명 어휘를 걷어낸다** — 평면 일러스트에서 조명은
   빛이 아니라 색면의 밝기 차다

## 5. 순서

```
씬 생성 → 3중 검수 → 둘 다 문제인 씬 재생성 → 재검수
                              ↑                    │
                              └────── 통과선 미달 ──┘
```

**이미지를 대량 생성하기 전에 한 편으로 먼저 검증한다.**
EP01에서 화풍 문제를 발견하지 못한 채 나머지 11편(430씬)을 생성했다면
같은 문제가 그대로 재현됐을 것이다.

## 프롬프트가 스스로 모순되지 않게

한 프롬프트 안에서 말이 엇갈리면 모델은 **금지 쪽을 따른다.**

씬986은 「기생들과 형편이 넉넉한 여인들이 옷에 아낌없이 돈을 썼거든요」인데
화면에 사람이 하나도 없었다. 프롬프트 본문에는 「인물: 비단을 몸에 대어 보는
여인들」이라고 적혀 있었는데, 같은 프롬프트 아래쪽에 이런 줄이 붙어 있었다.

```
이 화면에는 사람이 나오지 않습니다.
```

`cast` 와 `people` 칸이 비면 생성기가 이 줄을 붙인다. 원래는 빈 화면에 엉뚱한
사람이 그려지는 것을 막는 장치인데, **화면을 새로 짠 씬은 그 두 칸이 비어
있다.** 26컷이 이 상태였다.

> **「사람 없음」은 프롬프트의 「인물:」 칸이 실제로 비었을 때만 붙인다.**
> 칸에 사람이 적혀 있으면 그 사람을 그린다.

화면을 새로 짜는 도구는 `people` 을 함께 남기는 편이 낫다. 남기지 못했다면
생성기가 프롬프트에서 읽어 낸다.

## 코덱스는 NAS 에 못 쓴다

`codex exec --sandbox workspace-write` 는 NAS 심링크 경로에 파일을 만들지
못한다. 프로젝트 폴더를 목적지로 주면 **생성은 되고 저장만 조용히 실패**한다
— 27컷이 0/27 로 끝났고, 오류 메시지는 없었다.

> **로컬(`_imggen/…`)로 뽑은 뒤 프로젝트로 옮긴다.**

## 이어지는 컷은 같은 판에서 앞 컷을 본다

순차로 그릴 때, 방금 그린 컷은 아직 프로젝트에 붙기 전이다. 프로젝트만
보면 이어지는 컷이 **레퍼런스 없이** 그려진다. 이번 판의 출력 폴더를 먼저
본다.

## 사람이 있어야 할 화면과 아닌 화면은 미리 갈라 둔다

생성기가 짐작하면 두 방향으로 어긋난다.

  · 「여인들이 옷에 돈을 썼다」인데 사람이 하나도 없다
  · 현판을 보여야 할 컷에 사람 넷이 몰려 나온다

EP01에서 새로 그린 39컷 중 **24컷**이 그랬다.

> **화면을 짤 때 `people` 에 나오는 사람을 한 명씩 적는다.**
> 사물만으로 충분하면 빈 배열로 둔다 — 그때만 「사람 없음」이 붙는다.

| 사람이 있어야 한다 | 사물만으로 충분하다 |
|---|---|
| 누가 무엇을 한다 · 감정이 실린 순간 | 현판·문서·간판·장부가 곧 내용 |
| **사람이 주어인 말** (진학했습니다·돈을 썼습니다·판단했습니다) | 「구교리댁이라 불렀다」 → 현판 |

손이나 뒷모습만 나와도 사람이다. 나이와 옷차림까지 적어야 매번 다른 얼굴로
그려지지 않는다.

**프롬프트 본문에서 읽어 짐작하려 하지 말 것.** 생성용 프롬프트는 공냥 규격으로
다시 쓰이면서 「인물:」 표기가 사라진다 — 읽을 것이 없어 짐작이 실패한다.

### 수를 못 박아도 늘어난다

인원을 적어도 모델은 화면을 채우려 사람을 더 그린다(1명인데 3명). 못 박을
때는 **세어 보게 하고, 화면이 허전해도 사람으로 채우지 말라**고 함께 적는다.

### 검사할 때 최신 버전을 볼 것

기존 파일을 지우지 않으므로 재생성본은 `_v2` 로 쌓인다. 이름만 보고 열면
**고치기 전 그림을 검사하게 된다** — 실제로 7컷을 그렇게 잘못 판정했다.

### 시트는 이 컷에 나오는 사람만 붙인다

`cast` 는 그 씬에 **관계된 인물을 넓게** 적어 둔 것이라, 이 컷에 나오지 않는
사람까지 들어 있다. 그대로 붙이면 모델이 「첨부한 사람들」을 다 그린다 —
구인회 한 명짜리 화면에 구재서 시트가 따라붙어 노인이 하나 더 나왔다.

> **`people` 에 이름이 없는 시트는 붙이지 않는다.**
> 시트로 붙인 사람은 `people` 에서 빼고 센다 — 한 사람은 한 번만.

### 글자에 기대는 설계는 몇 번을 그려도 실패한다

이미지에는 **글자를 굽지 않는다.** 그런데 설계가 글자에 기대면 화면이
영원히 말을 못 한다.

씬968은 「동네에서는 그 집을 구교리댁이라 불렀다」를 **현판 클로즈업**으로
짰다. 현판은 빈 검은 판으로 나왔고, 세 번을 다시 그려도 같았다.

> **말을 물건으로 옮긴다.** 벼슬은 글씨가 아니라 **교지 두루마리의 붉은
> 인장과 학이 수놓인 흉배**로 보인다.

화면을 짤 때 이 제약을 알고 짜야 한다. 간판·현판·문서의 **글씨 내용**이
화면의 유일한 근거이면 그 설계는 무효다.
