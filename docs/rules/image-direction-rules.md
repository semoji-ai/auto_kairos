# 화면이 말을 하게 하는 규칙

> LG 1편을 시청자 셋에게 보였더니 100점 만점에 53점이 나왔다. 142컷 전부
> 화면이 서 있는데도 그랬다. 원인을 끝까지 따라가 보니 **셋 다 검사가
> 없어서** 생긴 일이었다. 규칙이 없어서가 아니다.

---

## 0. 한 문장

```
그림을 그린 뒤 「이 그림이 이 말을 하는가」를 묻지 않으면
프롬프트가 아무리 정확해도 화면은 말을 배신한다.
```

---

## 1. 화풍은 규격이고 상황은 목적이다

프롬프트의 **80%가 화풍 지시**였다. 그중 가장 긴 인물 비율 블록에 이렇게
적혀 있었다.

```
This is the single most important requirement of the image.
```

모델은 시킨 대로 했다. **화풍은 완벽하게 지키고 이야기를 흘렸다.**

```
씬993   프롬프트 「빈손을 펴 보이며 고개 숙이는 구인회, 그 옆 빈 나무 칸」
        나온 그림  선반 가득한 가게에서 웃으며 천을 펼치는 주인

씬1004  프롬프트 「고개를 돌리지 않고 걸어가는 아낙, 좌판을 비껴 지나는 발자국」
        나온 그림  맑은 하늘, 물건 가득한 좌판, 웃으며 걷는 사람들
```

### 화풍을 덜어내면 안 된다

덜어내면 그림체가 흩어진다. 시리즈는 그림체가 생명이다. **한 글자도 덜지
말고 순위만 바꾼다.**

```
① 비율 블록의 「가장 중요한 요구」를
   → 「시리즈 전체에서 똑같이 지켜지는 규격」으로

② 맨 앞에 Priority 를 둔다
   「Scene 이 말하는 상황과 인물의 행동이 이 그림의 목적입니다.
     그 뒤는 어떤 화풍으로 그릴지를 정하는 규격입니다.」

③ 맨 끝에 Must be visible 을 둔다
   화풍 블록 일곱 개를 지나오면 맨 앞의 상황이 묻힌다.
   끝에서 중경과 인물만 다시 적는다 — 모델은 끝을 무겁게 본다
```

이렇게 고친 뒤 13컷을 다시 그렸더니 **11컷이 회복됐다.** 그림체는 그대로다.

`build_image_prompts.py` 가 이 구조를 만든다.

---

## 2. 실물 자료는 근거가 있을 때만이다

판정문과 종류가 **정반대로** 저장돼 있었다.

```
씬1023  이유 「archive 부재, 긴장감 있는 재현 필요」  →  종류 search_image
씬1030  이유 「archive 부재, 무역항 분위기 재현」     →  종류 search_image
씬60    이유 「archive 사진 부재, 시대 재현 필요」     →  종류 search_image
```

「자료가 없으니 그려라」고 판단해 놓고 「실물 자료」로 찍혔다. 다음 단계는
그 말을 곧이곧대로 읽고 자료를 찾으러 갔고, 맞는 자료가 없으니 **시대만
맞는 아무 사진**을 붙였다.

```
「그의 이름은 안희제」      → 일본어 간판이 걸린 거리 사진
「살림집에서 문을 엽니다」   → 대형 공장 단지 전경
```

### 이유문으로 잡으면 안 된다 — 이유문은 낡는다

씬25·52·1039 는 이유에 「부재」라고 적혀 있지만 **그 뒤 좋은 자료를 실제로
찾았다**(침수한 구인회포목상점 사진, 허만정 초상, 럭키크림 실물).

> **관련성 칸으로 가른다.**
> 자료를 붙일 때 「이 자료가 이 말과 어떻게 이어지는가」를 적게 되어 있다.
> 그 칸이 비었다는 것은 이어진다는 근거가 없다는 뜻이다.

```
python3 scripts/check_kind_reason.py <EP> --apply
```

관련성이 빈 실물 자료 씬을 재현으로 되돌린다. LG 1편에서 6컷이 걸렸다.

## 3. 그린 뒤에 그림을 열어 본다

검사가 둘 있었는데 **둘 다 그림을 안 봤다.**

```
check_prompt_match.py      나레이션 ↔ 프롬프트     글과 글
check_asset_relevance.py   실물 자료 ↔ 나레이션    생성 이미지는 대상 밖
```

프롬프트는 맞았으니 검사는 전부 통과했다. 그림이 배신한 것은 화면에
올라갈 때까지 아무도 몰랐다.

```
python3 scripts/check_image_says.py <EP>
```

판정은 셋이다.

```
ok      그림이 그 말을 한다
weak    어긋나지는 않지만 그 말의 핵심이 화면에 없다
wrong   그림이 말과 반대이거나 딴 이야기를 한다   ← 반드시 다시 그린다
```

### wrong 으로 볼 것

- **말이 실패·부족·두려움인데 그림이 성공·풍족·활기인 경우.**
  가장 흔하고 가장 나쁘다. 소리를 놓친 사람은 정확히 반대로 읽는다
- 말이 가리키는 사람이 화면에 없거나 다른 사람인 경우
- 말이 정한 때와 곳이 그림과 다른 경우

LG 1편 첫 검사: **ok 63 · weak 35 · wrong 10.** 108장 중 45장이 제 몫을
못 하고 있었다.

## 4. 쪼갠 조각은 프롬프트를 물려받지 않는다

원고를 다시 쓰며 65씬을 174씬으로 나눴다. 조각들이 원래 씬의 `imageAsset`
을 통째로 물려받았고, 조각마다 **같은 프롬프트로** 그림이 나왔다.

```
씬20    「보통 첫 실패 뒤에는 물건을 줄이기 마련인데요」
씬997   「구인회는 반대로 구색을 늘렸습니다」            ← 반전

둘 다   「…두 선택 사이에서 풍성한 쪽을 고르는 구인회…」
```

**질문 컷에 답이 이미 그려졌다.** 반전이 나오기 전에 소진되고, 두 컷은
사실상 같은 그림이 된다.

`scene-splitting-rules.md` 6절에 「같은 프롬프트를 나눠 가진 씬 — 0」이
적혀 있었는데 **한 번도 세지 않았다.**

```
python3 scripts/check_split_health.py <EP>
```

`replan_direction.py` 가 앞뒤 문장을 보여 주되 제 문장만 그리게 하고,
같은 묶음으로 표시된 씬끼리는 확실히 다른 화면이 되게 한다.

## 5. 순서

```
① 씬을 나눈다              scene-splitting-rules.md
② check_split_health       프롬프트를 나눠 가진 씬이 0인가
③ check_kind_reason        실물 자료에 근거가 있는가
④ replan_direction         제 문장으로 화면을 짠다
⑤ build_image_prompts      화풍은 규격, 상황은 목적으로 조립
⑥ gen_scenes               그린다
⑦ check_image_says         **그림을 열어 보고 이 말을 하는지 묻는다**
                           wrong 이면 ④로 돌아간다
⑧ viewer_eval              시청자 셋에게 보인다
```

**⑦이 없으면 나머지가 다 무의미하다.** LG 1편은 ①~⑥을 다 하고도 53점이었다.
