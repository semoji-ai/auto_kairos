# 씬을 무엇으로 보여줄지 정하는 규칙

> 씬 분석 → 화면 결정 → 그림 생성 전체 순서. EP01 68씬을 실제로 돌려 보고
> 고친 판이다. 앞선 `infographic-decision-rules.md`를 이 문서가 대신한다.

---

## 0. 결론부터

**인포그래픽은 예외다.** EP01에서 재분석이 35씬을 인포그래픽으로 돌렸는데,
실제로 그려서 견줘 보니 **5씬만 인포그래픽이 맞았다.**

| | 인포 | 씬 그림 |
|---|---|---|
| 알아듣는가 | **22** | 8 |
| 보고 싶은가 | 5 | **25** |

이해는 도해가 빠르다. 그런데 **보고 싶지가 않다.** 도해가 이어지면 사람이
사라지고, 사람이 사라지면 이야기가 아니라 발표가 된다.

> **둘 다 이길 때만 인포그래픽.** 하나라도 씬 그림이 나으면 씬 그림이다.
> 이해가 조금 늦어도 사람이 남는 편이 낫다.

---

## 1. 순서 — 화면을 먼저 짠다

```
① 시각화 방식 분석          같은 내레이션의 장면·자료·도해 후보를 비교
② 도해 장면 설계             배경·실물/인물/사물·텍스트·라인·관계를 한 프레임에 설계
③ 완성 도해 이미지 제작      모든 요소가 들어간 한 장의 4K 장면 이미지
④ 완성 이미지 검수          의미·정확한 글자/수치·겹침·화질·보고 싶음 확인
⑤ 같은 문장의 장면 대안 비교 이해와 보고 싶음 모두 이길 때만 도해 선택
⑥ 선택된 완성 이미지 레이어 분리 fal Seedream 5.0 layerize 한 경로(아래 ⑥ 규칙)
⑦ 모션                      분리 레이어를 원래 배치로 재합성해 등장·강조·카메라 모션
⑧ 모션 QA                   정지 완성본과 최종 프레임 일치·가독성·시점 확인
```

**완료 판정:** 설계·프롬프트·요소 목록·타이포그래피 설정은 완성 도해가 아니다.
씬마다 내용에 맞는 에셋·텍스트·라인·배경을 **처음부터 한 장면 이미지 안에**
구성하고 그 완성 이미지를 눈으로 검수한다. 선택 후 그 이미지를 레이어로
나눠 모션을 준다. 별도 에셋을 먼저 만들어 빈 도해판에 하나씩 배치하는
기존 방식은 정본 제작 방식이 아니다. 글자와 선만 놓은 배치 시안은 그 문장에
필요한 시각 요소가 빠져 있다면 완성 도해가 아니다. 비교 대상인 씬 그림도
**같은 내레이션**을 표현해야 한다.
영상에서 순차 등장하는 도해는 핵심 단계마다 완성 프레임을 렌더한다. 원본
한 장을 보존하고, 분리 레이어를 재합성한 정지 프레임이 원본과 맞는지
확인한다. 렌더 파일과 검수 결과가 없으면 상태를
`plan_ready`/`render_qa_pending`에 두고 완료 수에 포함하지 않는다.
짧은 접속어 타이핑 화면도 의도된 예외일 뿐, 실제 렌더 검수 전에는 완료가 아니다.

### ⑥ 레이어 분리 규칙 (2026-10-07 확정)

- **방법은 하나 — fal `bytedance/seedream/v5/pro/layerize`.** 코드: `adobe/backend/fal_api.py`
  `layerize()`, 일괄 실행 `scripts/layerize_scenes.py`. Codex 마젠타 매트
  (`scripts/codex_matte_layers.py`), OCR 사각 자르기, layerkit 다시 그리기(`image-layers` 스킬)는
  **금지**다. 예외는 사용자 승인을 받고, 승인 사유를 실행 기록에 남긴다(`--approved`).
- **이름 목록 = 화면에 등장시킬 요소 전부.** Seedream 은 적은 이름만 떼어 낸다. 적지 않은 것은
  배경판에 남아 첫 프레임부터 보이고, 따로 뿅 등장하면 두 번 보인다(B231 사고 5회+).
  글자 덩어리(칩·카드 단위), 연결선, 화살표, 라벨, 건물에 딸린 나무·덤불·연기까지 넣는다.
  `names.json` 항목에 `"expected"`(등장 요소 목록)를 두면 호출 전에 빠진 이름을 알린다(`--strict` 면 중단).
- **배경은 z0(이름 없는 인페인팅 판)을 쓴다.** 이름 목록에 'background' 를 넣지 않는다 —
  넣으면 하늘·도로가 뚫린 배경 조각이 한 장 더 온다.
- **배경 잔상 검사:** 분리 뒤 요소 자리에서 원본과 배경판의 무늬를 견준다(`layer_report.json`,
  elements.json `bg_residue`). `flag` 는 요소가 판에 그대로 남은 것 — 이름을 고쳐 다시 나누거나
  그 자리를 지운다. 확인: 씬 첫 프레임(뿅 전)이 빈 배경인가.
- **글자는 AE 라이브 텍스트가 기본.** 분리된 글자 PNG 는 위치·크기 기준으로만 쓰고, 화면 글자는
  같은 폰트의 라이브 텍스트로 다시 놓는다(잘린 글자·바탕 사각째 오린 글자 방지).
- 조립(`scripts/build_ae_layer_scenes.py`)에서 원본 한 장은 **꺼 둔 가이드 레이어**다 — 켜 두면
  요소가 원본과 겹쳐 두 번 보인다.

**에셋을 먼저 만들면 안 된다.** 있는 재료로 화면을 맞추게 되어 늘어놓기가
나온다. EP01에서 157장을 먼저 뽑아 놓고 배치를 짜다 이 함정에 빠졌다.
완성 장면의 내용과 구도를 먼저 확정한 뒤 그 장면을 한 장으로 제작한다.

**②와 ③ 사이를 건너뛰면 안 된다.** 숫자로는 멀쩡한데 그려 놓으면 기호가
라벨에 파묻히고, 흐름인데 구분선이 가운데를 가르고, 「844가마」가 자루 하나로
그려져 있다. 셋 다 좌표만 봐서는 알 수 없다.

## 2. 인포그래픽이 이기는 자리

| 이길 때 | 예 |
|---|---|
| **「없음」을 보여야 한다** | 「독립 근거가 확인되지 않았다」 — 재연으로는 그릴 수 없다 |
| 수치가 합쳐지거나 환산된다 | 2,000 + 1,800 = 3,800 = 쌀 844가마 |
| 둘을 견준다 | 내려놓은 것 ↔ 새로 잡은 것 |
| 구조가 바뀐다 | 기둥 둘이 빠져도 남는 것 |

첫 줄이 가장 중요하다. **도해만 할 수 있는 일**이다.

## 재연이 이기는 자리

사람이 무엇을 한다 · 감정이 실린 순간 · 공간의 공기가 내용이다 ·
인물이 이어지는 구간(도해가 끼면 사람이 끊긴다).

## 3. 화면 문법 — 늘어놓지 않는다

화면이 **한 문장**이어야 한다.

- **항을 묶는다** — 「아버지 2,000원 + 구철회 1,800원」이 한 덩어리로 세로
- **기호로 잇는다** — `+` `=` `→`. 항과 항 **사이 빈 자리**에 두고 라벨과
  세로로 6% 이상 띄운다
- **구분선은 대비할 때만** — 흐름에 그으면 이야기가 끊긴다. EP01 다섯 씬이
  전부 이 잘못을 저질렀다
- **결론을 키운다** — 가장 중요한 항이 가장 크고 라벨에 강조색
- **제목을 단다** — 한 줄. 판을 깔 때는 글자만큼만(가운데 정렬은 폭을 늘리지
  말고 옮겨서)
- **넷 안팎** — 다섯을 넘으면 시선이 흩어진다(내용이 요구하면 일곱까지)

## 4. 배경과 글자

씬 그림이 이미 있다. 도해를 흰 바탕에 따로 만들 수도, 그 위에 얹을 수도 있다.

| 배경 | 언제 |
|---|---|
| `grid` | 화면이 오롯이 도해일 때. **계산·비교는 거의 여기다** |
| `scene` | 그림이 한산하고, 얹을 것이 그림이 말하지 않는 것일 때 |
| `scene_blur` | 장소·분위기는 남기되 도해를 읽혀야 할 때 |
| `map` | 「어디」가 내용일 때 |

**그림이 이미 같은 내용을 말하면 얹지 않는다.** EP01 씬15가 그랬다 — 장터
그림 위에 「비단·혼례·돈」 이름표를 얹었더니 전부 군더더기였다.

글자는 **연성체(BMYeonsung)** 로 통일한다. 읽히는 방식은 배경이 정한다.

| 대비 | 언제 |
|---|---|
| `plain` | 밝은 바탕에 먹색 |
| `shadow` | 어두운 그림 위 흰 글자 |
| `box` | 그림이 복잡할 때 — 글자 뒤 반투명 판. 가장 확실하다 |

기호는 그림 배경 위에서 어두운 원판에 흰 글자로 얹는다. 작고 옅으면 화면이
문장이 되지 않는다.

## 5. 검수에서 찾는 사고

이름을 붙여 둔다. 전부 실제로 났던 것들이다.

| 이름 | 무엇 |
|---|---|
| 겹침 | 기호가 라벨을 덮음, 요소끼리 포개짐 |
| 화면밖 | 가장자리에서 잘림 |
| 묻힘 | 배경 그림 위 먹색 글자 |
| 쓸데없는선 | 흐름인데 세로 구분선 |
| 군더더기 | 배경 그림이 이미 말하는 것을 또 얹음 |
| 뜻이틀림 | 「844가마」인데 자루 하나, 「합계」인데 빈 궤짝 |
| 나열 | 항이 묶이지도 이어지지도 않음 |

「뜻이틀림」은 좌표로 못 고친다. 그림을 다시 그려야 하므로 `pending_asset`으로
남긴다.

---

## 6. 되돌린 것은 되살아나지 않는다

「씬 그림이 낫다」고 정한 씬은 조립할 때 건드리지 않는다(`_pick` 판정을 읽는다).
이걸 안 보면 조립할 때마다 인포가 되살아난다 — 실제로 28씬이 그렇게 되돌아왔다.

되돌려도 **설계와 에셋은 파일로 남는다.** 언제든 다시 켤 수 있다.

---

## 7. 정본은 `scene_specs.json` 이다 — 옛 재분석 파일이 아니다

원고를 다시 쓰고 씬을 다시 나눈 날, 도해 단계가 통째로 헛돌았다. 세 도구가
「무엇이 도해인가」를 **`_imggen/<EP>_mode.json`(재분석 결과)** 에서 읽고
있었기 때문이다. 그 파일은 **옛 씬 경계**를 가리킨다.

| 도구 | 그날 벌어진 일 |
|---|---|
| `plan_infographic_layout.py` | 도해 22씬 중 12씬만 설계 대상이 됐다 |
| `compose_infographics.py` | 35씬을 훑고 4씬만 조립됐다 |
| `gen_info_assets.py` | 새로 생긴 8씬의 요소가 0장이었다 |

> **화면 종류는 `scene_specs.json` 의 `visual_kind` 가 정본이다.**
> 재분석 결과는 **요소 목록으로만** 쓴다. 목록에 없으면 설계가 부르는 것을
> 그대로 그린다.

원고가 바뀌면 설계도 다시 짠다 — `plan_infographic_layout.py --force`.
씬 경계가 그대로라고 설계가 그대로인 것이 아니다. 말이 바뀌면 화면도 바뀐다.

## 8. 판단은 데이터에 남아야 한다

「그려서 견줘 씬 그림이 낫다」고 정한 씬 4개가, 도해는 없는 채 **종류만
「도해」로** 남아 있었다. 판정 파일에는 있는데 `scene_specs` 에는 없었다.

그려서 견준 판정이 글 판단을 이긴다 — 그 순서가 **파일이 아니라 상태에**
찍혀야 한다. 조립할 때 종류까지 되돌린다.

## 9. 걸러지는 것이 정상이다

EP01 에서 도해는 이렇게 줄었다. 단계마다 다른 것을 본다.

```
글 판단 22  →  설계에서 6 걸러짐  →  16  →  옛 비교 판정 4  →  12씬
             (요소가 하나뿐이라        (그려서 견준 결과가
              도해가 성립 안 함)        글 판단을 이긴다)
```

「요소가 하나뿐이면 도해가 아니다」가 설계 단계의 그물이다. 합산도 환산도
대비도 없이 수치 하나만 있는 화면은 도해가 할 일이 없다.
