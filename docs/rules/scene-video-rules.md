# 씬 비디오 프롬프트 규칙

> 정지 씬 이미지를 힉스필드로 움직이는 컷으로 만들 때의 기준.
> 디아지오편 26컷을 실제로 뽑고 고쳐 가며 세운 판이다.

---

## 0. 먼저 물을 것 — 이 움직임이 무슨 말을 하는가

**「이 그림에 무슨 움직임이 어울리나」로 시작하면 안 된다.** 그렇게 쓰면
숨·천·물결·연기만 붙은, 예쁘지만 아무 말도 안 하는 컷이 나온다.

물어야 할 것은 이것이다.

```
① 이 씬의 나레이션이 주장하는 것은 무엇인가
② 그 주장을 움직임이 질 수 있는가, 아니면 장식만 되는가
③ 질 수 있으면 — 그 변화가 곧 이 컷의 움직임이다
④ 못 지면 — 그때만 「살아 있게 하는」 움직임
```

### 검사

**나레이션을 지우고 화면만 봤을 때 움직임이 무언가를 말하는가.**

디아지오 109씬이 그 예다. 나레이션은 「앙심을 품은 피터가 물길을 막아버린다」
인데, 처음 쓴 프롬프트는 이랬다.

```
❌ 물이 둑에 막혀 되돌아 소용돌이친다 · 인물이 천천히 숨 쉬며 둑을 내려다본다
```

막는 것까지는 넣었는데 **막아서 무슨 일이 벌어지는지**가 없다. 처음과 끝이
같아서, 소리를 끄면 그냥 사람이 서 있는 그림이다.

```
✅ 둑 위쪽으로 물이 차오르고, 아래쪽 물길의 수위가 눈에 띄게 내려가
   젖은 돌바닥이 드러난다. 피터는 그것을 내려다보며 입꼬리가 천천히 올라간다.
```

**사건이 있는 씬은 시작과 끝이 달라야 한다.**

---

## 1. 씬을 두 갈래로 가른다

| 갈래 | 무엇 | 움직임 |
|---|---|---|
| **사건** | 누가 무엇을 한다 · 무엇이 바뀐다 · 실패하거나 성공한다 | **시작과 끝이 다르다.** 변화가 곧 내용 |
| **상태** | 사물의 구조를 보인다 · 분위기를 깐다 · 마무리 | 살아 있게만 — 숨·물결·연기·빛 |

디아지오 26컷의 실제 갈래.

```
사건   109 물길 막기 · 112 실패한 위스키 · 136 선물을 고르는 손
상태   127~132 잔 정물 · 142 마무리 풍경 · 123 수상 진열
```

**26컷 중 상당수를 사건인데 상태로 썼다.** 안전하게 가려다 그렇게 됐다.

---

## 2. 프롬프트 구조 — 씬별 움직임 + 공통 꼬리

### 씬별 움직임 (사람이 쓴다)

나레이션과 그림을 함께 보고 한 문단. 무엇이 어떻게 바뀌는지 적는다.

### 공통 꼬리 (늘 붙인다)

```
Flat 2D vector illustration in exactly the attached style — smooth flat
colour planes, no outlines, no 3D shading, no photographic lighting.
Preserve the artwork exactly; only add the motion described above.

Keep the time of day, sky colour and overall lighting exactly as in the
attached frame — do not change it over the shot.

Keep each character's face shape, hairstyle and clothing exactly as in the
attached frame. Facial expression may change if the motion calls for it.

No background music or score. Natural on-location sound only.

Camera holds completely still.
```

**셋째 문단을 잘 읽을 것.** 처음에는 「얼굴을 그대로 두라」고만 썼는데, 그러면
**표정이 바뀌는 것까지 막힌다** — 109의 웃음이 그래서 안 나왔다. 생김새와
표정은 다른 것이다.

넷째 문단이 필요한 이유는 미니맥스 H3 에 **오디오 스위치가 없어서**다.
`generate_audio` 같은 값이 없고 소리는 늘 붙어 나오므로 프롬프트로만 지시한다.
확실히 하려면 애프터이펙트에서 원본 오디오를 끄고 현장음을 따로 얹는다.

---

## 3. 실측 — 무엇이 통했나

빛 고정과 얼굴 고정은 **재서 확인했다.** 첫 프레임과 끝 프레임의 평균 RGB 다.

```
공통 꼬리 없이 (100씬)   하늘이 노을로 물들고 언덕 색이 따뜻해짐 · 얼굴이 흔들림
공통 꼬리 넣고 (101씬)   96.6 → 96.4    변화 없음
공통 꼬리 넣고 (132씬)  110.7 → 110.5   변화 없음
```

---

## 4. 모델의 한계

**한 장에서 출발해 10초를 만든다.** 화면의 큰 부분을 새로 지어내야 하는 변화는
잘 못한다.

```
✅ 수위가 내려가 젖은 돌이 드러난다      정도의 변화
❌ 물길이 완전히 마른 바닥이 된다        새로 지어내야 하는 것
```

크게 바꿔야 하면 **시작·끝 두 장을 준다** — H3 는 `end_image` 를 받는다
(`end_image` 는 `start_image` 가 있어야 한다).

---

## 5. 길이와 요금

```
길이 = 씬 길이 + 1초, 정수로 올림
상한 = 15초        (넘기면 CLI 가 거절한다)
요금 = 초당 4크레딧  (정비례)
```

**너무 짧으면 실패한다.** 디아지오 106씬(씬 길이 2.09초)을 4초로 두 번 보내
둘 다 실패했고, **5초로 올리자 통과**했다. 오류 메시지는 남지 않는다.

씬보다 비디오가 짧아지는 경우(15초 상한)는 마지막 프레임을 정지로 늘리거나
그 씬만 이미지로 둔다.

---

## 6. 계정은 결재일 순서로 쓴다

구독이 여럿이면 크레딧이 계정마다 따로 들어오고 **결재일에 초기화된다.**
많이 남은 쪽부터 쓰면 갱신이 코앞인 계정이 끝까지 안 쓰이고 매달 그만큼
날아간다.

```bash
python3 -m backend.hf_accounts list          # 계정과 잔액(쓸 순서대로)
python3 -m backend.hf_accounts order a,b,c   # 갱신 임박순으로
```

`backend/hf_accounts.py` 가 `HOME` 을 갈아 계정을 나눈다. 생성할 때 앞선
계정을 바닥까지 쓰고 넘어간다. **업로드도 같은 계정에서 해야 한다** — 계정이
다르면 그 UUID 를 못 찾는다.

---

## 7. 보낼 때

`--wait` 를 빼면 작업 ID 만 받고 바로 끝난다. **26편을 한꺼번에 보내고 나중에
거두는 편이** 하나씩 기다리는 것보다 훨씬 빠르다(1시간 반 → 20분).

거둘 때는 `generate list` 를 훑어 **프롬프트 앞머리로 씬을 짝짓는다** —
작업 ID 를 못 받아도 이 방법으로 되찾을 수 있다.
