# 무엇이 공유되고 무엇이 갈려도 되는가

> 저장소를 하나로 합친 뒤의 규칙. 어도비와 리모션이 같은 폴더를 보는데,
> **모든 것이 같아야 하는 것은 아니다.** 어디까지 같아야 하는지 못박는다.

---

## 왜 이 문서가 필요한가

전에는 v3 프로젝트를 `adobe/projects/` 로 통째로 복사해 썼다. 같은 편이 두 곳에
있으니 v3 에서 그림을 다시 뽑아도 패널에는 옛 그림이 그대로였고, 손으로 옮기다
패널에서 안경을 지운 세 씬을 덮을 뻔했다.

지금은 한 폴더를 본다. 그런데 이번엔 반대 함정이 생긴다 — **갈려도 되는 것까지
억지로 맞추려는 것.** 애프터이펙트의 널과 리모션의 스프링은 같을 수 없다.

---

## 선

```
                재료 (공유)                      쓰는 법 (갈림)

  원고 · 레이아웃 · 이미지 프롬프트
  씬 이미지 · 레이어 파일 · 음성 · 비디오        ┌─ 리모션 렌더
  레이어의 뜻 (bbox · kind · z)          ───────┤
  모션 의도 («이 인물은 까딱인다»)                └─ 어도비 패널 → AE 조립
```

**의도는 공유하고 구현은 각자.**

| | 공유 | 갈림 |
|---|---|---|
| 레이어 파일 | `layers/*.png` · `*.svg` | — |
| 레이어의 뜻 | `layers/<sid>__elements.json` | — |
| 모션 의도 | `motion: "bob"` | — |
| 모션 구현 | — | AE 널+핑퐁 ↔ 리모션 `scaleY` 보간 |
| 좌표계 | — | 컴프 좌표 ↔ 씬 이미지 좌표 |
| 레이아웃 렌더 | — | `layouts.jsx` ↔ `.tsx` |
| 자막·오디오 얹기 | — | AE 텍스트 레이어 ↔ Remotion `<Audio>` |

---

## 정본은 `elements.json` 이다

레이어를 뗀 결과는 하나뿐이고, 거기 필요한 것이 다 있다.

```json
{"layer": "437e0232__1_John_Johnston_bearded_Sc_char",
 "kind": "character", "motion": "bob",
 "bbox": [885, 105, 1289, 944], "z": 4}
```

두 렌더러가 여기서 각자 필요한 모양으로 굽는다.

```
layers/<sid>__elements.json                  ← 정본
        ├─ manifest.json                      어도비 (build_manifest)
        └─ layers/<sid>__remotion.json        리모션 (build_remotion_layers.py)
                → build_layered_props.py → props.json → LayeredScene
```

**같은 원본에서 뽑으니 갈릴 수 없다.** 굽는 것을 잊으면 없을 뿐이지 어긋나지
않는다 — 이것이 사본을 두는 것과 다른 점이다.

> ⚠️ **리모션 쪽 형식을 새로 만들지 않는다.** 리모션에는 이미 사슬이 있었다
> (`animate_scene.py` 가 뗀 레이어 → `build_layered_props.py` → props). 어도비
> 레이어가 못 물린 것은 형식이 없어서가 아니라 **어휘가 달라서**였다. 붙일 때
> 옮기기만 하면 된다 — 세 번째 형식을 만들면 그때부터 갈리기 시작한다.

### 어휘가 다르다 — 옮기는 표

| 뜻 | 어도비 | 리모션 |
|---|---|---|
| 인물 | `kind: "character"` · `_char` 접미사 | `role: "person"` |
| 까딱임 | `moves: [{type: "bob"}]` | `bob: {amp, period, phase}` · `feet_bob` |
| 자리 | `position` · `scale` (컴프) | `bbox: [x, y, w, h]` (씬 이미지) |
| 배경 | 이름에 `__bg` | `bbox` 없음 |

`bbox` 표기가 다르다 — 원본은 `[l, t, r, b]` 인데 리모션은 `[x, y, w, h]` 다.
옮길 때 반드시 바꾼다.

## 모션 의도를 이름으로 추론하지 않는다

**`_char` 접미사는 어도비만 아는 규칙이다.** 그것으로 까딱임을 판정하면
리모션이 못 읽는다. 의도는 원본에 글로 적는다.

```
❌  파일 이름에 _char 가 있으면 까딱인다
✅  elements.json 에 motion: "bob" 이라 적혀 있다
```

어도비는 지금도 `_char` 를 보지만, 그것은 **옛 레이어를 위한 대비책**이고
정본은 `motion` 이다. 리모션 쪽(`build_layered_props.py`)도 같다 — `motion` 이
적혀 있으면 그것을 따르고, 없는 옛 메타에만 `role` 로 판정한다.

**인물이라고 다 까딱이는 것은 아니다.** 앉아 있거나 등을 돌린 인물이 까딱이면
어색하다. 그래서 판정을 종류(`role`)가 아니라 의도(`motion`)로 옮긴 것이다.

---

## 갈리지 않게 막아 둔 것 (한 폴더 안에서도 갈릴 수 있다)

| 무엇 | 어떻게 |
|---|---|
| 원고·TTS·자막 | 저장할 때 `scene_specs.json` 에도 함께 쓴다 |
| 선택된 이미지 | `imageRef` 를 바꾸면 `image_assets.json` 의 `selected` 도 맞춘다 |
| 씬 구조 | 번호가 밀리면 옛 번호(`_specs_num`)로 원고 쪽을 따라 맞춘다 |
| 그래도 어긋나면 | 시트 위에 붉은 띠 (`_specs_drift`) |
| 옛 복사 경로 | `import_v3` 를 막았다 (`AK_ALLOW_V3_IMPORT=1` 로만) |

## 새 렌더러를 붙일 때

리모션·애프터이펙트 말고 다른 것을 붙인다면 같은 자리에 낀다.

1. `elements.json` 을 읽는다 — 새 형식을 만들지 않는다
2. 그 렌더러가 읽는 모양으로 **굽는 스크립트**를 하나 둔다
3. 위 어휘 표에 한 줄을 더한다
4. **원본에 없는 뜻이 필요하면 원본에 필드를 더한다** — 렌더러 쪽에 숨기지 않는다

마지막 항이 중요하다. 까딱임을 `_char` 접미사로 숨겨 둔 탓에 리모션은 그것을
읽을 방법이 없었다 — 어도비가 자기 파일 이름 규칙으로만 알고 있었기 때문이다.
