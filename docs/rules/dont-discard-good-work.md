# 잘 만들어 둔 것을 버리지 않는다

> LG 1편에서 하루에 두 건을 잃었다. 씬2의 「무너진 기둥 위의 칩」이
> 「도장 찍힌 파란 원판」으로 덮였고, 씬985의 「구인회 — 매듭 — 허만정」이
> 통째로 떨어져 나가 후보 0장인 씬이 됐다. 둘 다 되살렸지만, 되살릴 수
> 있었던 것은 순전히 `.bak` 덕이었다.

---

## 1. 잃는 방식은 늘 같다

```
사람이 손으로 다듬어 좋아진다        ← 여기서 품이 들어간다
        ↓
나중 단계가 자동으로 다시 만든다      ← 좋아진 줄을 모른다
        ↓
조용히 이전 상태로 돌아간다           ← 아무도 알려주지 않는다
```

**나중 단계는 앞 단계가 손봐졌는지 모른다.** 그래서 자기가 아는 원본에서
다시 만들고, 그게 덮어쓰기가 된다. 악의도 버그도 아니고 **설계가 그렇다.**

---

## 2. 세 가지를 지킨다

### ① 범위를 좁힐 수 있어야 한다

한 장을 고치려고 전편을 다시 만들면, 손대지 않은 나머지가 전부 위험해진다.

```
정본을 쓰는 스크립트에는 --scenes 또는 --chapter 를 반드시 둔다
```

`compose_infographics.py` 에 이것이 없어서, 씬 하나를 조립하려면 37개를
전부 다시 조립해야 했다. 그 사이 레이아웃이 깎여 있으면 그대로 반영된다.

### ② 지우기 전에 덮어쓸 값을 본다

```
지금 값이 「사람이 검수한 것」이면 자동으로 지우지 않는다
지우려면 뜻을 밝히는 깃발을 요구한다   (--allow-revert 같은)
```

`designed: true` 에 `items` 가 있으면 설계를 마친 도해다. 판정 파일 하나로
그것을 떼어 내지 않는다.

### ③ 지켰으면 말한다

침묵하면 같은 일이 반복된다.

```
판정은 「그림」이지만 설계본이라 지킨 씬 1개: [985]
  판정이 낡았는지 보세요
  정말 떼려면 --allow-revert 를 붙이세요
```

---

## 3. 판정문은 낡는다

검수 판정은 **그때 조립된 화면을 보고** 내린다. 그 뒤 요소를 갈아 끼우면
판정의 근거가 사라지는데, **판정문은 그대로 남는다.**

```
씬985  판정  「현대식 반팔 차림이라 1947년으로 안 읽힌다 → 도해 말고 그림」
       그 뒤  시대 복식의 구인회·허만정으로 요소를 교체
       그런데  판정은 그대로 → 매번 도해를 떼어 냄 → 후보 0장
```

> **요소를 갈아 끼웠으면 판정도 갱신한다.**
> 갱신하지 않은 판정은 조용히 옛 결론을 계속 집행한다.

같은 폴더의 검수문(`ep01_check/s985.json`)에는 이미 정답이 적혀 있었다 —
「두 인물을 그 편의 캐릭터 시트로 교체」. 고칠 방법을 알고 있었는데도
판정만 낡은 채 남아 되밀고 있었다.

---

## 4. 없어졌다고 단정하기 전에

오늘 「캐릭터 시트가 다 없어졌다」고 판단하고 세 장을 새로 그렸다.
**하나도 없어지지 않았다.** 엉뚱한 파일을 세고 있었다.

```
그림은  images/image_assets.json    ← 여기 있다
        scene_specs.json 의 images   ← 여기가 아니다
```

> **없어졌다고 말하기 전에 파일을 직접 센다.**
> 잘못된 판정 위에서 하는 복구는 복구가 아니라 두 번째 손실이다.

---

## 5. 되돌릴 수 있게 둔다

```
정본을 쓰기 전에 shutil.copy2 로 .bak 을 남긴다
그림 파일은 지우지 않는다 — 버전을 올린다 (이미지 삭제 금지 규칙)
```

오늘 되살릴 수 있었던 것은 `.bak` 이 있었기 때문이다. 타임머신은 잡혀
있지 않았다. **백업이 없는 스크립트는 한 번의 실수로 끝난다.**
