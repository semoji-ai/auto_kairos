# auto_kairos 제품 구성 — 셋처럼 보이지만 둘이다

> v3(터미널·앱), AE 플러그인, 프리미어 플러그인. 셋을 어떻게 묶을 것인가.

---

## 결론

**저장소는 둘, 규격은 하나.** 프리미어는 새 제품이 아니라 **호스트 프로파일**이다.

```
auto_kairos  (우산 이름 — 저장소가 아니라 규격의 이름)
│
├─ auto_kairos_v3       기획 · 원고 · 자료 · 에셋 · 프로젝트 저장소
│                        터미널 + 대시보드, 앞으로 데스크톱 앱
│
└─ auto_kairos_adobe    CEP 확장 하나
                         backend/  공통 (분리·벡터화·매니페스트)
                         jsx/ae/   컴프·레이어
                         jsx/ppro/ 시퀀스·클립     ← 프리미어는 여기만 다르다
```

셋을 저장소 셋으로 가르면 **같은 백엔드를 두 번 유지**하게 된다.

---

## 왜 프리미어가 별도 제품이 아닌가

`cep/com.autokairos.pd/CSXS/manifest.xml`이 이미 호스트를 **목록**으로 받는다.

```xml
<HostList>
  <Host Name="AEFT" Version="[22.0,99.9]" />
  <Host Name="PPRO" Version="[22.0,99.9]" />   <!-- 한 줄 추가 -->
</HostList>
```

같은 확장이 두 프로그램에서 뜬다. 패널 UI·백엔드 호출·프로젝트 목록·에셋 관리가
전부 그대로다. **다른 것은 마지막 한 겹, JSX뿐이다.**

| | After Effects | Premiere |
|---|---|---|
| 단위 | 컴프 · 레이어 | 시퀀스 · 클립 |
| 합성 | 레이어를 겹쳐 쌓는다 | 트랙에 나란히 늘어놓는다 |
| 카메라 | 가이드 널에 키프레임 | 모션 효과 (스케일·포지션) |
| 레이어 분리 | **필수** — 2.5D의 근거 | 대체로 불필요 — 완성 컷을 얹는다 |
| 자막 | 텍스트 레이어 | 캡션 트랙 또는 그래픽 |

**분리한 레이어가 프리미어에서는 쓸모가 적다.** 프리미어는 「컷을 잇는」 도구라,
씬 이미지 한 장 + 오디오 + 자막이면 충분한 경우가 많다. 대신 AE에서 뽑은
5초 컷(mp4)을 클립으로 받는 흐름이 자연스럽다.

그래서 매니페스트를 **두 프로파일**로 낸다.

```
ae_manifest.json      컴프 · 레이어 · 가이드 널 · 키프레임
ppro_manifest.json    시퀀스 · 클립 · 마커 · 캡션
```

공통은 그 위의 `scenes.json`이다 — 씬 순서, 나레이션, 길이, 에셋 경로, 큐 시각.

---

## v3를 앱으로 만든다면

**다시 만들지 않는다.** 대시보드가 이미 있다(`app.py`, FastAPI + 템플릿).
Tauri나 Electron으로 그 로컬 서버를 감싸면 앱이 된다.

```
데스크톱 앱 (Tauri)
  └ 내부에서 uvicorn app:app 기동 → 창은 localhost:8080 을 띄운다
```

- UI 코드가 하나로 유지된다 (웹 = 앱)
- 터미널 사용도 그대로 남는다 (`auto-agent run …`)
- 앱은 **프로젝트 열기·진행 상태·에셋 검수**를 맡고, 무거운 실행은 지금처럼 CLI

굳이 네이티브로 다시 쓸 이유가 없다. 대시보드는 이미 탭 아홉 개를 갖추고 있다.

---

## 셋을 묶는 것 — 코드가 아니라 규격

세 프로그램이 공유하는 것은 **프로젝트 폴더 하나**다. 이것에 이름과 판을 붙인다.

```
kairos-project / 1
  scene_specs.json      v3 원본 (연출·자료·권리)
  scenes.json           관문 — adobe가 읽는다
  images/ audio/        에셋
  layers/               분리·벡터화 결과 (adobe가 쓴다)
  ae_manifest.json      AE 프로파일
  ppro_manifest.json    Premiere 프로파일
```

- **쓰는 쪽은 하나**다 — 각 파일마다 주인이 정해져 있다. v3는 `scenes.json`까지,
  adobe는 `layers/`부터.
- **판 번호를 올린다** — 필드가 바뀌면 `"version": "kairos-project/2"`. 읽는 쪽이
  모르는 판이면 명확히 거절한다.
- 규격 문서는 v3에 둔다(생산자 쪽). adobe는 그 문서를 참조하고 적합성 검사만 한다.

이게 「auto_kairos 체인」의 실체다. 저장소를 합치는 것이 아니라 **파일 규격을
제품 취급**하는 것이다.

---

## 그래서 무엇을 하나로 볼 것인가

| 하나로 | 갈라서 |
|---|---|
| 프로젝트 폴더 규격 | 저장소 |
| 브랜드·버전 이름 (auto_kairos 2026.8) | 릴리스 산출물 (앱 / 확장) |
| 프로젝트 저장소 위치 (`AK_PROJECTS_ROOT`) | 런타임 (venv / stdlib) |
| 에셋·오디오·자막 | 매니페스트 프로파일 (ae / ppro) |

버전은 **날짜 기반 한 줄로 함께 올린다**(`2026.8`). 사용자에게는 한 제품군으로
보이고, 안에서는 각자 배포한다.

---

## 순서

1. `AK_PROJECTS_ROOT`를 v3 output으로 — 패널이 v3 프로젝트를 그대로 본다
2. `scenes.json`에 `version` 필드 추가, 규격 문서를 v3에 작성
3. AE 쪽을 먼저 완성 (카메라·인포그래픽 인수인계 둘)
4. 프리미어는 `HostList` 한 줄 + `jsx/ppro/` — **AE가 안정된 뒤에**
5. v3 앱화는 마지막. 대시보드를 Tauri로 감싸는 것으로 충분

**프리미어를 먼저 벌이지 않는 것**이 중요하다. AE 쪽 매니페스트가 아직 움직이는
중인데 프로파일을 둘로 늘리면 양쪽이 계속 어긋난다.
