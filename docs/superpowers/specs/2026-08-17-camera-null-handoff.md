# 카메라(가이드 널) 이식 — auto_kairos_v3 시제품에서 넘김

> v3에서 씬 하나로 **레이어 분리 → 벡터화 → 나레이션 기반 카메라 무빙**까지
> 끝까지 돌려 봤다. 화질·타이밍·앞뒤 순서가 모두 확인됐다.
> 이 문서는 그 결과를 AE 가이드 널로 옮기기 위한 인수인계다.
>
> 시제품 위치 — `~/LocalProjects/auto_kairos_v3/scripts/render_camera.py`
> 결과 영상 — `~/LocalProjects/auto_kairos_v3/_imggen/ep03_anim/s041b/s041_lead2.mp4`

---

## 1. 왜 널인가

`build_scene.jsx`가 이미 씬마다 가이드 널을 만들고 모든 레이어를 페어런팅한다.

```javascript
var guide = comp.layers.addNull();
guide.name = s.prefix + "가이드";
guide.property("Position").setValue([W / 2, H / 2]);
il.parent = guide;
```

**가이드 널 하나에 키프레임을 찍으면 씬 전체가 카메라처럼 움직인다.** 새 구조가
필요 없다. 계층은 이렇게 된다.

```
가이드 널 (카메라)
  └ 까딱 널 (addBobNull, 인물별)
      └ 레이어 (SVG / PNG)
```

v3 시제품은 이 계층이 없어 화각 변환과 발 고정을 파이썬에서 따로 계산했다.
AE에서는 페어런팅이 대신한다.

---

## 2. 넘어오는 데이터 — `camera`

씬 매니페스트에 `camera` 배열 하나를 더한다. 없으면 지금처럼 정지 화면이다.

```json
"camera": [
  {"t": 0.0,   "rect": [0, 0, 1792, 1024]},
  {"t": 10.45, "rect": [0, 0, 1792, 1024]},
  {"t": 12.25, "rect": [412, 180, 819, 468], "ease": "70:30"},
  {"t": 15.45, "rect": [412, 180, 819, 468]},
  {"t": 16.65, "rect": [1180, 180, 819, 468], "ease": "ease"}
]
```

- `t` — 씬 시작 기준 초. 컴프 절대 시각은 `s.start + t`
- `rect` — **씬 이미지 좌표계**의 화각 `[x, y, w, h]`. 항상 컴프와 같은 비율
- `ease` — `linear` / `ease` / `70:30`

키가 둘 연속으로 같은 `rect`면 그 구간은 정지다. 정지 구간을 생략하지 말고
명시적으로 넣는다 — 안 그러면 AE가 두 키 사이를 계속 보간해 쉬는 구간이 사라진다.

---

## 3. rect → 널 Scale / Position

가이드 널의 원래 위치를 `P0 = (W/2, H/2)`라 하자. 자식은 바인딩 시점의 상대
위치를 유지하므로, 씬 좌표의 한 점 `c`는 다음으로 옮겨진다.

```
c' = P + (c - P0) * s
```

화각 `rect = (vx, vy, vw, vh)`의 중심이 화면 중앙에 오면 되므로,

```
s = W / vw                                  // 배율 (100 곱해 % 로)
c = (vx + vw/2, vy + vh/2)                  // 화각 중심
P = (W/2, H/2) - (c - (W/2, H/2)) * s       // 널 Position
```

**Scale은 X·Y 같은 값**을 쓴다. `rect`가 컴프 비율과 같으므로 왜곡이 없다.

> ⚠️ 씬 이미지가 컴프와 크기가 다르면(`1792×1024` vs `1920×1080`) `manifest.py`가
> 이미 굽고 있는 세로 기준 배율 `f`와 좌우 오프셋 `ox`를 `rect`에도 똑같이 곱한다.
> 좌표를 두 번 변환하지 않도록 `_scene_layers`와 같은 자리에서 처리하는 편이 안전하다.

---

## 4. 이징

| 값 | 뜻 | AE 키프레임 |
|---|---|---|
| `linear` | 등속 | 이징 없음 |
| `ease` | 부드럽게 | 양쪽 Easy Ease (영향 33%) |
| `70:30` | 느리게 → 빠르게 → 느리게 | **나가는 키 영향 70 / 들어오는 키 영향 30**, 속도 0 |

`70:30`이 기본이다. 카메라가 툭 출발하고 툭 멈추면 싸구려로 보인다.

---

## 5. 화각 잡기 — 인물이 크면 상반신으로

`rect`를 계산하는 쪽(v3)에서 이미 처리했지만, 패널에서 사용자가 대상을 고를 때도
같은 규칙이 필요하다.

인물을 화면 세로의 `tight` 비율로 잡으려면 `h = 인물높이 / tight`인데,
**이 값이 컴프보다 커지면 확대가 아니라 축소가 되어 검은 여백이 생긴다.**
실제로 박정희(626px)에 `tight 0.55`를 줬다가 화각이 1138px가 되어 그렇게 됐다.

그럴 때는 전신을 포기하고 **상반신**을 잡는다.

```
h = 인물높이 * 0.72
중심 y = 인물 top + 인물높이 * 0.30
```

그리고 마지막에 항상 `w ≤ W`, `h ≤ H`로 조인다.

---

## 6. 언제 움직이나 — **말보다 먼저 도착한다**

가장 중요한 규칙이다. 처음에 문장이 끝나는 시각에 카메라를 출발시켰더니
「박정희」가 들린 **뒤에** 그를 보여 줘서 늦었다.

```
❌ 12.63초 「박정희」 발음 → 그때 줌인 시작
✅ 10.45초 줌인 시작 → 12.25초 도착 → 12.63초에 이름이 들림
```

**동작의 끝 시각은 그 대상을 부르는 큐보다 0.3초 이상 앞선다.**
사람은 눈으로 먼저 보고 귀로 듣는다.

큐는 ElevenLabs 타임스탬프에서 자동으로 뽑는다 — `audio/<sceneId>.timestamps.json`이
글자 단위 시각을 들고 있어, 레이어 이름·고유명사가 처음 나오는 글자 위치의 시각을
쓰면 된다. 씬마다 손으로 적을 필요가 없다.

실측 예 (EP03 씬 41):

```
 6.86초 군사정부   9.38초 밀수    12.63초 박정희
14.69초 부산     15.01초 금성사  17.08초 라디오   18.74초 김해수
```

## 7. 한 씬에 동작은 둘 셋까지

계속 움직이면 멀미가 난다. 그리고 **마지막 동작은 씬이 끝나기 전에 멈춰야 한다** —
움직이는 중에 다음 씬으로 넘어가면 어수선하다. 시제품은 마지막 0.4초를 정지로
남겼다.

---

## 8. 함께 확인된 것 (카메라 밖이지만 관련)

**z 순서는 그림을 보고 정한다.** 이름 규칙으로 「가림 소품은 맨 위」라고 했더니
작업대가 **그 위에 놓인 부품까지** 덮었다. 부품은 배경판에 있는데 상판이 위로
올라간 것이다. 멀티모달로 앞뒤를 물으면 정확히 답한다.

```
bg → 인물 4(발 낮은 순) → 작업대 → 작업대 위 부품 → 바닥 상자
```

**책상을 떼면 책상 위 물건도 함께 떼야 한다.** 안 그러면 상판이 그것들을 덮는다.
분리 요청 이름에 「작업대」와 「작업대 위의 라디오와 진공관 부품들」을 함께 넣는다.

**층마다 SVG / PNG를 고른다.** 인물·큰 소품은 벡터가 좋고(2.2배로 당겨도 선이
살아 있다), **잔부품이 많은 층은 PNG**가 낫다 — Recraft가 작은 조각을 합쳐
구리 코일의 감긴 결과 진공관 내부가 사라졌다. `layers.json`에 `use_png: true`로
표시한다.

**Recraft는 납작한 그림을 400으로 거부한다.** `1297×215`가 그랬다. 정사각 캔버스에
얹어 보내고 얹은 위치를 기록했다가 나중에 그 자리만 잘라 쓴다(`svg_pad`).

## 9. 붙일 자리

| 파일 | 할 일 |
|---|---|
| `backend/manifest.py` | 씬에 `camera` 배열을 실어 보낸다. 좌표 배율 `f`·`ox`를 `rect`에도 적용 |
| `cep/.../jsx/build_scene.jsx` | `buildSceneGroup`에서 가이드 널에 Scale·Position 키프레임을 찍는다 |
| 패널 | 씬별 카메라 미리보기·수정 (후순위) |

`build_scene.jsx`의 `applyMoves`가 레이어 단위 모션을 다루듯, 가이드 널 단위로
`applyCamera(comp, guide, s.camera, t0, W, H, fps)` 하나를 더하면 된다.
